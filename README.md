# NutriCalc Pro 2.0

Учебная модель подбора меню по энергии и БЖУ с ограничениями порций и явной проверкой отклонений.

Исходный проект: Георгий Образцов. Код версии 2.0, исправления и новый поиск подготовлены с помощью ИИ. При защите следует различать исходную работу автора, полученную помощь и самостоятельно проверенные результаты.

## Файлы

- `index.html` — страница сайта.
- `app.js` — расчёты, поиск, хранение плана и интерфейс. В Node.js экспортирует расчётный API через CommonJS.
- `styles.css` — стили, адаптация под телефон и печать.
- `tests.cjs` — автоматические проверки без сторонних пакетов.
- `.nojekyll` — отключение обработки Jekyll при публикации статических файлов.

Откройте `index.html` в современном браузере. Сборка и установка пакетов не нужны. Скрипты, стили и шрифты не скачиваются из CDN. Для переноса одним файлом предусмотрена отдельная автономная версия HTML.

## Что изменено

1. Поля проверяются до вычислений; пустой ввод не заменяется скрытыми значениями по умолчанию. Недопустимые параметры не создают план.
2. Основной режим работает с заданной учебной калорийностью. Формула Миффлина — Сан Жеора доступна отдельно для возраста 19–78 лет, как в исходной выборке. Она остаётся оценкой; коэффициенты активности и сценарии ±15% — допущения модели.
3. Цели по БЖУ участвуют в оценке результата. Суточные фактические суммы и процентные отклонения видны пользователю.
4. Порции ограничены относительно базовых масс. Шаг поиска — 10 г. Энергия рассчитывается из фактической массы и БЖУ, без подстановки целевой калорийности в результат.
5. Переключение дня и недели показывает один сохранённый план. Поля после изменения требуют нового расчёта, устаревший результат скрывается.
6. Сохранение выполняется в localStorage. Повреждённый или устаревший план отклоняется, восстановленные показатели пересчитываются. Ошибка хранилища не мешает расчёту. Доступны удаление сохранённой копии, экспорт JSON и печать.
7. Нет зависимости запуска от Lucide, Tailwind CDN или Google Fonts.
8. Убраны неподтверждённые возрастные нормы нутриентов и лечебные обещания. Названия блюд не содержат фиксированного количества яиц или орехов, которое противоречило бы масштабированию.
9. Элементы формы имеют подписи; переключатели доступны с клавиатуры. Печать использует чёрный текст на белом фоне.

## Метод

База содержит 5 вариантов для каждого из 4 приёмов пищи. Поиск рассматривает все 5⁴ = 625 сочетаний блюд. Для каждого сочетания массы порций уточняются координатным поиском на сетке 10 г, до 12 проходов. В каждой координате проверяются ближайшие к минимуму квадратичной функции разрешённые значения массы.

Функция качества:

`Q = 4eE² + eP² + eF² + eC² + 0.2 × Σ(Emeal/Etarget − share)²`

Здесь `e = (факт − цель) / цель`, модельные доли энергии приёмов пищи — 25%, 35%, 15%, 25%. Эти веса и доли являются параметрами модели. Глобальный оптимум по всем массам не гарантируется. Алгоритм выбирает варианты с учётом повторений, но разнообразие не гарантируется.

Если найденные варианты укладываются в заданный допуск одновременно по энергии и каждому макронутриенту, они получают соответствующий статус. Если нет, показываются найденные приближения с предупреждением. Это не доказательство отсутствия допустимого решения. Если найден только один вариант в допуске, он может повторяться все семь дней, а кнопка другого варианта отключается.

При начальной учебной цели 2400 ккал, БЖУ 25/30/45%, порциях 50–150% и допуске 10% поиск находит один подходящий вариант. Это результат работы данного поиска на данной базе, а не доказательство единственности решения во всей сетке размеров порций.

## Ограничения данных

20 блюд, плотности БЖУ и базовые массы перенесены из первоначального проекта. Подтверждённые рецептуры отсутствуют. Энергия определяется моделью 4/9/4 ккал на грамм белков/жиров/углеводов. Все результаты относятся к этой учебной базе. Сайт не назначает питание и не подтверждает полезность, безопасность или лечебный эффект меню. Аллергии, медицинские состояния, витамины и минералы не оптимизируются.

## Проверки

В среде с Node.js:

```sh
node tests.cjs
```

24 автоматические проверки: проверка полей и возрастного диапазона; независимый расчёт формулы; соответствие энергии БЖУ; полный перебор на подзадаче с фиксированными порциями; сохранение ограничений и правильность сумм на 30 сценариях; восстановление повреждённых данных; обработчики интерфейса с имитацией DOM; отсутствие сетевых зависимостей.

Эти проверки не заменяют визуальный осмотр в браузере. До выпуска следует открыть файл на компьютере и телефоне, проверить размеры 360/768/1280 px, печать дня/недели, скачивание JSON, перезагрузку и работу клавиатуры. В текущей среде открытие локального HTML в браузере было заблокировано; визуальная и печатная проверка не заявляются выполненными.

## Публикация в GitHub Pages

Подготовленное назначение: `gemigramota-glitch/nutricalc-pro`. Репозиторий создан пользователем; комплект подготовлен для размещения в его корне.

1. Войти в GitHub под нужным аккаунтом и создать публичный репозиторий `nutricalc-pro`.
2. Загрузить содержимое этого каталога в корень репозитория: `index.html`, `app.js`, `styles.css`, `README.md`, `tests.cjs`, `.nojekyll`. Загружать распакованные файлы, а не сам ZIP.
3. В Settings → Pages выбрать Deploy from a branch, ветку с загруженными файлами и каталог `/ (root)`, затем сохранить.
4. Дождаться успешной сборки Pages и открыть адрес, который покажет GitHub. Ожидаемый адрес: `https://gemigramota-glitch.github.io/nutricalc-pro/`. Он не считается действующим до проверки публикации.
5. На опубликованной странице проверить расчёт, вкладки дня/недели, экспорт и печать. Отдельный сервер и платные сервисы не требуются.

Для публикации с помощью CLI сначала требуется действующий вход: `gh auth login --hostname github.com`.
